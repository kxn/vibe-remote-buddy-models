## 新增的两个已有适配样本

沿用应用生成的稳定 ID `remote.muawdc1x`（YYYKQ 17键）与 `remote.mubbvfjx`（移动16键），文件名使用可辨识机型名称，避免为相同样本生成重复 ID。

来源是 buddy-0.11.4 保存的 schema 2 适配证据：两者均有完整224字节 Report Map、9个完整报告引用及覆盖所有按键的验证记录。所有普通键的 report/usage 与保存键表逐项一致。语音来自 F8 状态报告（248/1），解码记录为16kHz、codec 2，已有录音样本分别46720与29120个，decode_error、sdk_error、end_reason均为0。沿用已验证的 hid-ico.v1 驱动和保存的普通键表，不额外合成 HID 语音触发键。

两者 Map CRC32C 均为 `7e6df9bf`，报告引用相同；17键比16键多静音键（report 3 / usage 226）。协议所需 HID 服务为1812，不要求不存在的FD00服务。采集到的PnP source为5，不属于标准的1/2，故不作为硬性识别条件。两份模板在协议指纹层面均可匹配，必须保留全部候选并确认键码，不能虚构唯一指纹或依靠设备地址强行区分。

新增机型的默认名称、动作取自已保存适配包；外观取自此次用户编辑。提取时没有修改本地覆盖或已配对槽位。
